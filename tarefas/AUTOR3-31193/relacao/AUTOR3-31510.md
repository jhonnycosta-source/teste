[Prêmio Informado] - Implementar comunicação com o serviço para salvar o prêmio informado - auto-cotacao-web

Description

VISÃO DO USUÁRIO:

Eu como Analista Interno
Quero acessar a tela dedicada para alteração de prêmios das coberturas permitidas
Para que eu possa informar o motivo, a justificativa e os novos valores de prêmio, atualizando o orçamento e exibindo o indicador de alteração na oferta

ESCOPO - Lista de Funcionalidades

✅  Resumo da tarefa
Conectar a tela de alteração de prêmios às APIs do BFF (cotacaobff.yaml), implementar o fluxo de confirmação via modal, tratamento de retorno, redirecionamento e atualização visual do card na tela de flexibilização.

🛠️ Implementação Técnica

auto-cotacao-web:

Contratos e Carregamento de Dados (cotacaobff.yaml)

1.1. Tipagem e Mapeamento: Ajustar DTOs/interfaces baseando-se no contrato do cotacaobff.yaml.

1.2. Consulta Inicial (GET):

Ao abrir a tela, disparar GET /ofertas/{numeroCotacao}-{versaoCotacao}-{numeroOrcamento}/premios.

Caso já existam dados salvos, preencher automaticamente Motivo, Justificativa e valores de coberturas.

Fluxo de Salvamento e Modal de Confirmação

2.1. Modal de Confirmação: Ao clicar no botão "Salvar" (habilitado), exibir o Modal de Confirmação.

2.2. Disparo do Salvamento (PUT): A requisição PUT para o BFF só deve ser enviada quando o usuário clicar em "Confirmar" dentro do modal.

Pós-Salvamento e Feedback Visual

3.1. Redirecionamento: Após sucesso no salvamento (status 2xx), redirecionar o usuário para a tela de flexibilização.

3.2. Badge no Card: Exibir a marcação/badge "Prêmio alterado" no card correspondente na tela de flexibilização.

Testes Unitários Front-end

Testes de chamadas de API (GET e PUT), exibição/interação do modal de confirmação, estados de loading/erro e renderização condicional do badge.

CRITÉRIOS DE ACEITE

CENÁRIO 1 - Redirecionamento e Acesso Autorizado à Rota
Dado que a toggle AUTO_COTACAO_PREMIO_INFORMADO está ativa,
E o usuário é Analista Interno,
E o motivo de congelamento é EM_FLEXIBILIZACAO_INTERNA,
Quando o usuário clicar no link "Alterar prêmio" do card da oferta,
Então a aplicação deve redirecionar o usuário para a nova tela de alteração de prêmio

CENÁRIO 2 - Bloqueio de Acesso Direto via URL
Dado que uma das condições de guarda não foi atendida (toggle inativa, perfil incorreto ou motivo diferente de EM_FLEXIBILIZACAO_INTERNA),
Quando o usuário tentar acessar a URL da tela diretamente pelo navegador,
Então a tela não deve ser exibida e o usuário deve ser redirecionado para fora da rota

CENÁRIO 3 - Carregamento de Dados Existentes (GET)
Dado que a tela de alteração de prêmio foi aberta,
Quando a consulta inicial ao BFF retornar dados de prêmio informado já existente,
Então a tela deve exibir os campos preenchidos com o motivo, justificativa e valores de coberturas recuperados

CENÁRIO 4 - Restrição de Edição por Cobertura
Dado a lista de coberturas exibida na tela,
Quando a tabela/lista for renderizada,
Então o sistema deve permitir a alteração do valor do prêmio somente para as coberturas Casco, RCF e APP, mantendo todas as demais em modo somente leitura

CENÁRIO 5 - Validação de Formulário (Botão Salvar Desabilitado)
Dado a tela de alteração de prêmio aberta,
Quando o campo Motivo ou Justificativa estiver vazio ou não preenchido adequadamente,
Então o botão "Salvar" deve permanecer desabilitado

CENÁRIO 6 - Modal de Confirmação de Salvamento
Dado que os campos obrigatorios estão preenchidos e o botão "Salvar" está habilitado,
Quando o usuário clicar no botão "Salvar",
Então o sistema deve exibir um modal de confirmação. A requisição PUT para o BFF só deve ser enviada se o usuário clicar no botão "Confirmar" do modal

CENÁRIO 7 - Sucesso no Salvamento, Retorno e Badge no Card
Dado que a alteração de prêmio foi salva com sucesso,
Quando o processo for finalizado,
Então o sistema deve:

Redirecionar o usuário de volta para a tela de flexibilização.

Exibir o indicador/marcação de "Prêmio alterado" no card da oferta flexibilizada.

CENÁRIO 8 - Recálculo Dinâmico em Tempo Real
Dado que o analista está na tela de alteração de prêmio,
Quando ele digitar ou alterar o valor de prêmio de uma cobertura editável,
Então o sistema deve recalcular e atualizar imediatamente na tela os valores de Valor Líquido, IOF, Valor Total e a Variação (%)

CENÁRIO 9 - Validação de Valores Inválidos (Zero ou Negativo)
Dado o campo de digitação de prêmio da cobertura,
Quando o analista tentar informar um valor igual a zero ($0$) ou negativo ($<0$),
Então o sistema deve recusar o valor/bloquear o campo e manter o botão "Salvar" desabilitado
